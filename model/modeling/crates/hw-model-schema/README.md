# hw-model-schema

`hw-model-schema` is a reusable, runtime-neutral vocabulary for describing
fixed byte records and register maps. It supplies explicit scalar codecs, typed
metadata, checked record views, deterministic validation, exact-start register lookup,
and a format-neutral streaming export boundary. The facade re-exports the declaration
macros, so downstream crates normally depend on this crate rather than on the
procedural-macro implementation crate.

## Upgrading from 0.1

Version 0.2 adds definition graphs, optional discovery, typed analysis passes and
independent record/register backends. Export APIs are intentionally changed:
replace `Exporter`, `Artifact` and `ArtifactSink` implementations with domain
backend callbacks that receive `std::io::Write`. `generate` writes to an ordinary
writer; `prepare` exposes per-entry source identity and emission when the application
chooses separate destinations. The caller owns flushing and publication.

Manual register-map builders must handle the result of `with_placements(...)`;
attachment validates the supplied topology instead of accepting unchecked metadata.
Nested manual storage crosses the same validation boundary as root storage.
The facade pins the compatible 0.2.0 macro crate; applications normally depend only
on the facade. Rust raw identifiers are supported in declarations; descriptive
metadata retains source spelling while generated helper symbols omit `r#`.

## Upgrading from 0.2

Version 0.3 replaces raw-AST renderer contexts with restricted `export::record::Context`
and `export::register::Context` capabilities and shallow `export::view` inputs.
Analysis passes retain full semantic traversal; renderers recurse through bound
visits using `value::Emit`, including explicit reference expansion. Rename backend
`root` callbacks to `entry`; output names and MIME types now belong to the caller,
so `OutputMetadata` and its callback are removed. `PreparedEntry::name()` exposes
source identity for application-owned output routing.

Structural callback defaults recurse through their children; detailed documentation
uses the short-description formatter unless overridden. Add custom analysis before
generation when a target needs extra derived facts. Optional `export-sv` and
`export-uvm-regs` backends join C and Veryl. The declaration DSL, codecs, register
access and wire layouts retain their existing behavior. The unchanged macro
implementation remains pinned to 0.2.0; it does not require a duplicate release.

## Definition graphs and optional discovery

`ast::SchemaSet` selects definitions; `resolve()` follows their references,
deduplicates by Rust type identity, checks by-value cycles and returns a
`SchemaGraph`. Distinct fields referencing the same type remain distinct edges.
`definitions()` is sorted by canonical Rust path; `dependency_order()` puts
dependencies before their users. `roots()` distinguishes explicit selections from
automatically reached dependencies. Type IDs are process-local, not serialized ABI
keys. Distinct definitions with an ambiguous canonical path are rejected.

```rust
use hw_model_schema::{record_schema, union_schema, ast::SchemaSet};
record_schema! { pub record Payload { endian: Little, fields: { value: u32 } } }
union_schema! { pub union Message { cases: { Payload(Payload) } } }
let mut selected = SchemaSet::new();
selected.add_record::<Message>(); // Payload is reached through its variant edge.
let graph = selected.resolve()?;
assert_eq!(graph.definitions().count(), 2);
assert_eq!(graph.roots().len(), 1);
# Ok::<(), hw_model_schema::ast::GraphError>(())
```

Ordinary records, both union forms, reusable bits, registers and register maps
provide definition metadata. Union edges retain branch names and tagged wire
codes; their selector path is descriptive, never an inferred untagged-union codec.
Bits have no intrinsic byte order: each embedding owns that choice. Custom
`SchemaLayout` and `RegisterLayout` implementations default to opaque metadata;
override `schema_definition()` to expose dependencies. Metadata producers must be
deterministic and describe one definition per type. An integer containing an
address does not imply a schema reference to the pointed-to memory object.

`add::<T: DescribeSchema>()` accepts any described definition.
`add_definition()` also supports application-provided metadata.
`add_map_instance::<T>("name", &[arguments])` retains a separately named, checked
configuration: two counts of the same map remain two instances of one definition.
`instances()` exposes those bindings and their concrete placement geometry.

The optional, default-off `discovery` feature uses `inventory` registrations
generated by the existing macros. No catalog attribute, extra scope, source scan
or module wrapper is needed. `SchemaRegistry::discover().select_module("crate::mod")`
selects linked definitions using segment-bounded defining Rust paths, including
private definitions. Selection is an export choice, not a visibility/security
check. Reexports do not change identity. Unlinked crates and disabled `cfg` items
are not discoverable. `SchemaSet::extend(other)?` combines discovery and manual
selections; neither manual construction nor dependency traversal requires this feature.

Discovery relies on the host target's startup/registration support. The standalone
`tests/fixtures/schema-discovery` consumer verifies renamed facade imports,
cross-crate discovery of unused definitions under release/LTO and a user-written
DOT dependency-graph backend with **no builtin exporter enabled**. This is the
tested host configuration, not a qualification of every inventory target.

## AST, analysis and emit

Version 0.3 separates unrestricted semantic analysis from restricted render
capabilities. See the migration notes above for changes from the 0.2 API.

The existing DSL parser feeds two macro expansion branches: ordinary Rust types,
accessors and codecs, and canonical schema AST construction. No generated Rust
source is parsed. The Rust behavior and wire layouts remain independent of emit.

`ast::Node` borrows original records, fields, unions, cases, bits, enums,
registers, maps and placements. `children()` traverses containment;
`references()` traverses definition dependencies, retaining repeated edges.
The resolved graph gives inline cases their own anonymous record definitions. External codec cases reference named
definitions. Storage words are physical layout attributes, not logical AST fields.
Constants retain their source expression and wire value. Collected child views
may be sorted without changing source declaration order.

Generation has three steps:

1. Resolve a `SchemaSet` dependency graph.
2. Build `analysis::AnalyzedSchema` with optional root `Bindings`.
3. Call `export::generate(&schema, backend, output)` with a record or register
   backend and a caller-selected output destination.

`AnalyzedSchema::analyze` runs the default sequence directly from a `SchemaSet`.
The sequence in `analysis/pipeline.rs` calls separate resolve, validate, layout
and simplify passes. Their preconditions and results follow explicit Rust calls;
adding or splitting a pass does not change the backend protocol. The completed
schema has no public constructor or mutable access to its units. Source edits
require another analysis, so stale layout results cannot be emitted accidentally.

```rust
use hw_model_schema::{
    register_map, register_schema,
    ast::SchemaSet,
    analysis::{AnalyzedSchema, Bindings},
};
register_schema! { pub register Status { width: 4, endian: Little,
    access: ReadOnly, reset: Zero(0), writable_mask: 0, fields: {} } }
register_map! { pub map Device(n: usize) { alignment: 4,
    placements: [pub statuses: Status[n]] } }
let mut selected = SchemaSet::new();
selected.add::<Device>();
let graph = selected.resolve()?;
let symbolic = AnalyzedSchema::from_graph(&graph, &Bindings::new())?;
let mut bindings = Bindings::new();
bindings.bind::<Device>(&[3]);
let concrete = AnalyzedSchema::from_graph(&graph, &bindings)?;
assert_eq!(symbolic.units().count(), concrete.units().count());
# Ok::<(), Box<dyn std::error::Error>>(())
```

Analysis retains declarations and attaches checked layout results. Logical field
bounds and overlaps are checked independently of storage lowering. Bindings
specialize selected unreferenced roots; shared generic definitions need separately
named instances or separate requests. Instance identity remains distinct from
definition identity.

Manually assembled ASTs cross the same validation boundary. Field extents must
match scalar, bits, referenced value or union storage; union alternatives must fit
their envelope. Scalar encoding metadata must agree with its source placement.
Bit ranges, overlapping members, enum codes and constant values are checked before
generation. Register AST fields reuse the runtime register validator through a
borrowed field slice. Packed byte placements remain supported; this does not add a
natural-alignment requirement to individual record fields.

`AnalyzedSchema::record` accepts an explicit `RecordDefinition`.
`AnalyzedSchema::opaque` accepts manual `RecordSpec` storage without inventing source
fields. Both validate before emission. `AnalyzedSchema::register_map` accepts a
resolved permission projection. Export callbacks receive complete mathematical
layouts or concrete register maps, retaining effective access, masks, bank identity
and holes. Source `MapView`/`PlacementView` analysis states are not backend inputs.

Record and register domains have independent `Backend` traits and typed nodes.
Processing uses `analysis::Pipeline` and `analysis::Pass<Input>`. Each pass owns
its output and error types; `Pipeline::new(input).run(pass)` passes that output
to the next explicitly selected stage. The built-in `Resolve`, `Validate`,
`LayoutSchema` and `Simplify` stages use the same protocol as custom passes.
Generators can insert analysis between these stages. `AnalyzedSchema::from_graph`
remains the convenience path through validation, layout and simplification.

For late target analysis, a pass can accept `(&schema, data)` and return
`(&schema, new_data)`. `prepared.generate(|data| Backend::new(data), &mut sink)`
borrows those results and runs the ordinary generator. Backends without extra
analysis keep using `generate(&schema, backend, &mut sink)`. Validated and laid-out
states expose immutable source. Their consuming `into_source()` discards the
stage result before a transformation; the changed source must be validated and
laid out again. Custom pass data is explicitly carried by its result type.

Passes can walk `traversal::record::definitions(&schema)` or
`traversal::register::definitions(&schema)` without
implementing a renderer. Record `ctx.referent()` follows the current source
reference as a bound visit. Its ancestors include the actual reference site, so
two uses of a shared definition retain separate paths. Ordinary `children()`
continues to traverse source containment without implicitly expanding references.
The C record renderer's optional `CRecordAnalysisPass` computes occurrence offsets
from source ancestry, indexed by occurrence `NodeId`; this computation is not
part of the mandatory core flow. `traversal::source` also exposes pre-layout
traversal. `DefinitionId` identifies a Rust declaration during discovery;
`NodeId` identifies roots, children and reference-site occurrences during passes
and generation. IDs are structural within an immutable schema, not persistent
handles across arbitrary source edits.

Shared bits/enums use `export::value::Backend`, implemented independently by each
domain renderer. A handler receives a shallow borrowed `export::view` of its node.
Import `export::value::Emit` to recurse through `self.emit(ctx.current(), writer)`
and `self.emit_all(ctx.children(), writer)`. The blanket implementation owns dispatch;
backends cannot replace it. The render-only `Context` is bound to the current node. Its
`value::Backend::Domain` selects the record or register dispatcher
for the unified generation entry. Recursion supplies the call stack. No begin/end
events, per-type Render forwarding traits or mutable render stack are involved.
Definition dependencies are generated once; referring members remain distinct.

Contexts and `Visit` handles are created by the generator. Root and child nodes use
the same visit type; `root(ctx)` is the entry callback for each selected unit, not
a separate node-access protocol. An analyzed `Unit` can represent a source definition
or a projected view; `AnalyzedSchema::units()` iterates both in dependency order.
Filtering or sorting visits preserves their lexical context; backends cannot rebind
a raw node to another context. Render contexts expose root identity, names,
documentation, parent identity and scalar layout facts. They do not expose the
AST, analyzed schema, raw ancestors or child collections. `Visit` exposes only
shallow metadata for filtering and sorting; dispatch retains its lexical binding.
Analysis passes continue to use the complete `traversal` API. Register contexts also
expose normalized register paths and locations. Target-specific naming and selection of
template or concrete output remain backend choices.

Field views describe placement only: they expose no value type. Scalar, enum and
bits occurrences dispatch to their own value callbacks with complete encoding
facts. Packed enums carry bit width; byte enums carry scalar width and byte order.
References are explicit occurrences with a single dependency edge. Only the
`reference` callback receives the bound target visit; it may emit a target symbol
or invoke shared dispatch to expand it. Ordinary render contexts cannot resolve
or follow references. Analysis traversal still exposes the complete source graph.
Register reference callbacks also receive target access and identity metadata.
Their target visit is definition-scoped: its formal parameters belong to the
target, while the callback's use-site context provides constructor argument visits.
This keeps child and parent parameter scopes distinct when names differ.

Register-context `parameters()` returns the active unbound parameters, independently of
which children have been visited. `lexical_parameters()` supplies bound parameter
visits for rendering function signatures through the same callbacks.
`declared_parameters()` and `bindings()` retain
the original declaration and concrete arguments. Backends need no parameter cache
or mutable semantic scope stack.

Record, register and field callbacks receive their complete shallow metadata;
individual size, access and reset attributes do not require separate callbacks.
Register fields default to the shared `value::Backend::bit_field` callback.
The shallow `view::BitField` uses a lossless `usize` sibling ID for both source
forms, while the context keeps the actual occurrence identity, register owner and
enum children. A target overrides `register_field` only when it needs different
register-specific syntax. Source metadata and Rust-side field ID types are unchanged.

Completed layout properties use one `layout_property` callback with a kind, name
and optional relative placement owner. The formula is a bound child visit; only
the `expression` callback receives format/evaluate access. `ctx.layout(kind)`
selects a bound property when target syntax needs it elsewhere. Backends do not
recover ownership from raw nodes. Structural callbacks traverse children by default;
layout properties and constructor arguments recurse into their expression leaves.
Named references remain references unless the backend expands them. Leaf callbacks
produce no output by default. Detailed documentation defaults to the short-description
formatter; either callback can still be overridden independently.

Documentation participates in the same dispatch: `short_description` and
`description` receive present source text with a `DocumentationOwner` and the
current domain scope. Summary precedes detail, explicit empty text is retained,
and placement fallback is preserved. Targets own comment syntax, line splitting
and escaping. `value::emit_documentation` and `documentation_fragments` also serve
physical-storage renderers. Opaque record members use shared `storage_member`
callbacks; their bit fields and enum values use the same bound child dispatch.
Analysis prepares tagged-union wire fields at their reference use sites. They are
available as bound `union_storage()` visits when a
target chooses physical storage accessors instead of semantic case expansion.
Documentation lines are not separate IR nodes.

- `export-c-header` enables `CRecordBackend` and `CRegisterBackend`. Byte accessors use checked
  physical storage layout; semantic backends retain the original AST.
- `export-veryl-layout` enables `VerylRecordBackend` and `VerylRegisterBackend`. Their metadata packages describe
  layout, not register storage, bus behavior or hardware effects. Package aliases
  use ASCII letters, digits and underscores, starting with a letter or underscore.
  Anonymous `_`, names starting with `__`, and Veryl/SystemVerilog keywords are
  rejected before emission. The generated format is checked with Veryl 0.22.
- Both features are default-off; custom backends need neither builtin.

Veryl emits direct scalar layout functions (`extent`, member `offset`, `count`
and `stride`) from completed expressions; it does not emit a `Geometry` structure
or an aggregate `geometry()` function. C retains its aggregate `_Geometry` API,
whose fields and assignments are rendered through the same analyzed leaf callbacks.

The layout pass resolves the source `MapLayoutPlan` into complete mathematical
attributes attached to the same declarations. Child arguments, extents and ordered
placement dependencies are substituted before generation. The simplify pass
folds constants and arithmetic identities. `CompleteMapLayout` and each placement
expose formulas evaluable with only root parameter values; backends never resolve
`ChildLayout` or `PlanValue`. Original parameter bindings and references remain
available. Read-only constraints retain positive counts, alignment, bounds and
nonoverlap requirements for unbound parameters; `evaluate` checks these as well.
Generated layout helpers assume arguments satisfying those constraints.

Both symbolic and bound maps use one `register_map` callback. `layout_property`
visits its analyzed attributes; it is not a second map representation. The default
walk follows the declaration once. A backend needing flat concrete addresses may
explicitly emit `ctx.projected_children()`; bank templates similarly offer
`ctx.instances()`. Permission-only views are authoritative: traversal preserves
masked fields, sparse original indices and holes without reopening hidden source
registers. Reference expansion and concrete bank expansion are separate operations.

These are semantic layout attributes and borrowed traversal views, not another
target-code IR. Target functions, local variables, assignments and byte access
algorithms remain backend implementation choices.

`LayoutExpr::visit` owns left-to-right source expression folding. Checked evaluation,
constructor-scope validation and analysis share it. The nonrecursive
`export::expression::ExpressionSyntax` supplies spelling for analyzed expressions;
`format_expression` owns their recursive formatting. Backends choose target syntax
and any intermediates needed to render those formulas. Portable constructor
expressions support literals, parameters, constant paths, parentheses and checked
addition/subtraction/multiplication. Unsupported Rust expressions remain explicit
errors; ordinary generated Rust constructors are not restricted to that subset.

`SymbolScope` shares collision bookkeeping; escaping and identifier rules belong
to each target. The default-feature register listing and standalone discovery DOT
backend demonstrate application-defined whole-node emission:

```sh
cargo run -p hw-model-schema --example register_listing
```

## What it owns

Schemas are descriptive. Scalar fields use `u8`, `u16`, `u32`, or `u64` with an
explicit `Little` or `Big` byte order. Records also compose bits, enums, nested
layouts and unions; layout geometry may introduce padding. Register declarations
carry typed IDs, width, alignment, access, reset, and writable-mask metadata. Maps place
registers or nested maps in one declaration-ordered layout.

`RegisterWindow<M>` owns one generated register value at a caller-selected base.
Its exact-leaf MMIO access checks window bounds, width, permissions and writable
bits. Synchronous per-access hooks let hardware validate a proposed write, refresh
a read or apply effects after acceptance; hooks are never stored. Failed validation
or a rejecting hook preserves the window values and read destination. Effects on
external captures cannot be rolled back.

`register_dispatch!` evaluates access expressions lazily and falls through only on
`RegisterAccessError::OutsideWindow`. Gaps inside a window and rejected accesses are
terminal. Dispatch requires non-overlapping windows, as established by generated
placements. Applications own ring structure, entry publication, cursors, DMA, reset
epochs and IRQ behavior. Storage backends, bus observation, actors, concurrency and
execution remain outside this crate.

This crate exposes no ring protocol or ring types and has no normal dependency on
PDMA crates. An entry type parameter does not make application cursor rules schema
mechanics; PDMA defines those rules in its contract crate.

## Reuse

Requires Rust 1.96 or later. Add the facade crate to use its types and macros:

```toml
[dependencies]
hw-model-schema = "0.3.0"
```

Enable `export-c-header` for the C header exporter. The default feature set is empty.
An application may rename the dependency without changing macro expansion:

```toml
[dependencies]
his = { package = "hw-model-schema", version = "0.3.0", default-features = false }
```

It can use the same renamed-dependency form from a Git revision when the repository is
available to that downstream project:

```toml
[dependencies]
his = { package = "hw-model-schema", git = "https://example.com/your-org/hw-model-schema", rev = "<reviewed-revision>", default-features = false }
```

The macro expansion resolves the facade correctly when it is renamed to `his`. Pin a
revision appropriate to the consuming project; the URL above is a template, not a
publication endpoint.

## Declare and inspect a schema

### Descriptions

Inside declaration macros, `#[short_description = "..."]` and
`#[description = "..."]` attach optional text to schema definitions and members:

```rust
hw_model_schema::record_schema! {
    pub record CopyRequest {
        endian: Little,
        fields: {
            #[short_description = "Transfer length"]
            #[description = "Number of bytes to copy.\nZero performs no transfer."]
            length: u32,
        },
    }
}
```

The same attributes describe register fields, reusable bits, and register-map
placements. The outer schema macro consumes these attributes; they are not separate
attribute macros. Both accept string literals, including raw and multiline strings.
Duplicate attributes and non-string values are errors.

Descriptions live in existing schema metadata as `Documentation`. A placement may
override its reused definition's text; each omitted item falls back independently.
An explicit empty string overrides rather than inherits. Parent map descriptions do
not become descriptions of child registers. Descriptions never change layout,
encoded bytes, access permissions, or reset values.

Generated Rust documentation and the optional C exporter use these descriptions.
Metadata preserves the source text; the C renderer neutralizes comment delimiters,
trigraphs and line splicing when writing comments. An undocumented declaration keeps
its existing C output. Other documentation tools can read the same metadata without
parsing Rust source or generated comments.

Run the complete example to generate a described record and register header:

```bash
cargo run -p hw-model-schema --features export-c-header --example documented_schema
```

### Layout and values

`record_schema!` declares record-level `endian`, optional `alignment`, and ordered
fields whose aligned offsets and final size are generated.
Its field types are scalars, nested records, `enum(storage)`, `bits(storage)` with
LSB0 half-open ranges such as `0..5` or inclusive ranges such as `0..=4`, and `tagged_union`
cases selected by a local or nested `self` tag. Enum values may omit assignments after
an explicit value. Union fields may
use wider wire `storage`, while unused union slots and undeclared bits are reserved
zero. A scalar `{ const: OtherRecord::record_size }` is derived during encoding and
validated during decoding. Generated `*Values` types therefore expose the semantic
record directly rather than requiring a second handwritten overlay.
`bits_schema!` gives one LSB0 bit layout a stable name, typed value, field
identities, inferred minimum scalar extent, and checked codecs. Inferred records refer
to it with `bits(Name)`, while registers use `fields: Name`; both embeddings therefore
share the exact field names, ranges, semantic types, and metadata. Byte order belongs
to the containing record or register rather than to the bits schema.
`register_schema!` declares an offset-free register with explicit width and alignment.
Its inline `fields` use the same bit language: one-bit fields have typed `bool`
accessors and wider ranges use the smallest matching unsigned integer. `0..=0` selects
only bit 0, `7..=9` selects three bits, and `0..=63` selects an entire 64-bit word.
The existing `..` spelling stays half-open; both forms can be mixed in a declaration.
Inclusive endpoints are normalized at parsing, so codecs, metadata and overlap checks
use the same internal layout. Descending, overlapping and out-of-storage ranges are
rejected, as are inclusive endpoints whose conversion would overflow.
Field IDs are inferred in declaration order. Undeclared bits are preserved by field writes, and the
writable mask may not select an undeclared bit. `register_map!` declares an optional
exact `extent`, ordered `placements: [...]`, and optional `access: [...]` tree. Access
paths name existing placements and generate borrowed views of the root bytes. A
placement may omit its offset; the macro aligns the high-water mark. A placement without
brackets is scalar; `[count]` declares an indexed bank, including `[1]`. Bank strides
always use the aligned child extent. Maps and registers share
one composable `RegisterLayout`; access namespaces define no layout, IDs, or storage.

Scalar record enums and enum bit fields share declaration parsing, discriminant
validation, typed conversions and enum metadata. A bit field adds its range before
the enum declaration:

```rust
use hw_model_schema::bits_schema;

bits_schema! {
    pub bits Status(u8) {
        code: 0..2 => enum {
            variants: { Idle = 0, Active = 1, Fault = 2 },
        },
    }
}
```

The same field syntax works inside register fields and record `bits(storage)`.
Named bits layouts can be embedded in both containers. Enum variants may carry
`description` and `short_description`. Values must fit the declared bit range;
duplicate names/codes and overflowing implicit values are rejected during expansion.
Unknown raw codes produce a located `UnknownTag` error when decoded as an enum.
Register raw storage still preserves those codes and undeclared bits. An owned
enum field setter is infallible because every variant fits by construction; typed
reads remain fallible. Reading named register `fields()` is now fallible as well.
The C exporter emits unshifted discriminant constants and variant documentation
from the shared metadata, including nested and repeated placements.

Every generated schema boundary has a distinct raw owner and semantic value. `Decode`
converts the raw owner into the semantic value, `Encode` performs the reverse, and the
macros provide matching concrete `TryFrom` implementations. Record and register owners
apply their declared byte order internally, while named bits use an endian-neutral
integer raw owner. A register value defaults to its declared reset value; a register-map
value recursively composes its child defaults.

The following executable example declares a record, two registers, and one ordered
map, then encodes both generated owned-value types.

```rust
use hw_model_schema::{bits_schema, record_schema, register_schema};
# use hw_model_schema::{
#     Access, BitsFieldDefinition, BitsFieldSpec, BitsLayout, BitsValueError, Endian,
#     Decode, Encode, FieldSpec, SchemaCodec, SchemaLayout, RecordSpec, RegisterCodecError, RegisterDefinition,
#     RegisterLayout, RegisterValueError, ResetKind, ScalarKind, SchemaCodecError,
#     SchemaMemberIdentity, SchemaLocation,
#     inferred_align_up, inferred_field_id, read_scalar, write_scalar,
# };

bits_schema! {
    pub bits CommonFlags(u16) {
        ready: 0..1,
        mode: 8..12,
    }
}

record_schema! {
    pub record FlagRecord {
        endian: Big,
        fields: { flags: bits(CommonFlags), },
    }
}

register_schema! {
    pub register FlagRegister {
        width: 4,
        endian: Little,
        access: ReadWrite,
        reset: Zero(0),
        writable_mask: 0xf01,
        fields: CommonFlags,
    }
}

# fn main() -> Result<(), Box<dyn std::error::Error>> {
let flags = CommonFlagsValues { ready: true, mode: 5 };
assert_eq!(FlagRecord { flags }.to_bytes()?, [0x05, 0x01]);
let mut register = [0xf0, 0xa0, 0x5a, 0xc3];
FlagRegisterViewMut::new(&mut register)?.set_fields(flags)?;
assert_eq!(register, [0xf1, 0xa5, 0x5a, 0xc3]);
# Ok(())
# }
```

```rust
use hw_model_schema::{record_schema, register_schema};
# use hw_model_schema::{
#     Access, Decode, Encode, Endian, FieldSpec, OrderedRegisterMapSpec, SchemaCodec, RecordSpec,
#     RegisterCodecError, RegisterDefinition, RegisterLayout, RegisterLayoutGeometry, RegisterMapPlacement,
#     ResetKind, ScalarKind, SchemaCodecError, SchemaCoordinate, SchemaMemberIdentity,
#     SchemaLocation,
#     checked_align_up, checked_placement_end,
#     read_scalar, write_scalar,
# };
# mod register { pub use hw_model_schema::register::*; }
# mod register_map { pub use hw_model_schema::register_map::*; }

record_schema! {
    pub record Packet {
        alignment: 4,
        endian: Little,
        fields: {
            sequence: u32,
            code: u16,
        }
    }
}

register_schema! {
    pub register Status {
        width: 4,
        alignment: 4,
        endian: Little,
        access: ReadOnly,
        reset: Zero(0),
        writable_mask: 0,
        fields: {},
    }
}

register_schema! {
    pub register Producer {
        width: 4,
        alignment: 4,
        endian: Little,
        access: ReadWrite,
        reset: Zero(0),
        writable_mask: 0xffff_ffff,
        fields: {},
    }
}

hw_model_schema::register_map! {
    pub map DeviceMap {
        alignment: 4,
        extent: 16,
        placements: [
            pub status: Status,
            pub producer: Producer[2],
        ],
    }
}

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let packet = Packet { sequence: 0x1122_3344, code: 0x5566 };
    let packet_bytes = packet.to_bytes()?;
    assert_eq!(packet_bytes, [0x44, 0x33, 0x22, 0x11, 0x66, 0x55, 0, 0]);
    assert_eq!(Packet::from_bytes(&packet_bytes)?, packet);
    assert_eq!(Packet::SPEC.validate(), Ok(()));
    let values = DeviceMapValues {
        status: StatusValues::new(7),
        producer: [ProducerValues::new(11), ProducerValues::new(13)],
    };
    let encoded = values.to_bytes()?;
    assert_eq!(&encoded[..12], &[7, 0, 0, 0, 11, 0, 0, 0, 13, 0, 0, 0]);
    assert_eq!(DeviceMap::STATUS.offset(), 0);
    assert_eq!(DeviceMap::PRODUCER.offset(), 4);
    assert_eq!(DeviceMap::PRODUCER.stride(), 4);
    assert_eq!(DeviceMapValues::from_bytes(&encoded)?, values);
    Ok(())
}
```

Generated record value types expose `SPEC`, offset constants, immutable/mutable
checked views, and a composable `SchemaCodec`. The declared record name is the
owned semantic value type; `NameRaw`, `NameView`, and `NameViewMut` provide byte
storage and checked views. Ordered maps expose typed placement metadata, checked
nested views, and a generated `*Values` owned codec.

Field names must not collide with generated members in the same type (for example,
register `value`/`raw`, record `values`/`from_bytes`, or a getter named `set_foo`
alongside field `foo`). These conflicts are diagnosed at the field declaration.
Record fields named `bytes` are supported; tagged-union discriminators may appear
after their payload in wire order.

Validation is deterministic. `RecordSpec::validate` checks duplicate IDs, duplicate
names, scalar widths, alignment, extents, and overlaps, in that order and declaration
order within a pass. `RegisterSpec::validate` checks width, writable mask, then reset
value. Map validation checks duplicate IDs/names, duplicate expanded starts, register
metadata, layout/extents, then expanded-range overlap. The macros reject malformed
declarations at compile time; runtime `validate` is available for application-assembled
metadata.

`RegisterMapSpec::locate` is deliberately exact-start-only: it returns `None` for an
interior byte or an unmapped offset. It does not validate transaction width, alignment,
access permission, or reserved ranges, and it has no bus transaction or storage effect.
Those checks belong to the application runtime.

## Canonical definitions and reference expansion

`SchemaSet::resolve` constructs the canonical definition graph from macro-generated
or hand-built declarations. Builtin integers remain values. Records, unions, bits
and enumerations become definitions referenced by their containing members,
including an enumeration with a builtin integer representation. The construction
API accepts the original inline DSL shape; the resolved graph has one uniform
definition/reference representation.

`Definition::origin()` retains `Origin::Named` or `Origin::Inline`. Anonymous
identities derive from their declaring source and structural member path; display
names do not define identity. Repeated uses of a named type share its canonical
definition. A union's external selector remains on the use-site reference, not
on its independent payload definition. Normalization does not change Rust codecs,
record geometry or register ownership.

Rendering chooses expansion per reference. There is no Inline/Outline rewrite
pass and no copied all-inline tree. A reference callback can emit a type name or
call the ordinary emitter on its supplied target visit:

```rust
use hw_model_schema::{
    analysis::{AnalyzedSchema, Bindings},
    ast::SchemaSet,
    export::{record, value::{self, Emit}, view, Visit},
    record_schema,
};
use std::io::{self, Write};
record_schema! { pub record Payload { endian: Little, fields: { value: u32 } } }
record_schema! { pub record Packet { endian: Little, fields: { payload: Payload } } }
struct Text;
impl value::Backend for Text {
    type Domain = record::Domain;
    type Error = io::Error;
    type Context<'a> = record::Context<'a>;
    fn scalar(&mut self, _: view::Scalar, ctx: Self::Context<'_>, out: &mut dyn Write) -> io::Result<()> {
        writeln!(out, "{}", ctx.path())
    }
}
impl record::Backend for Text {
    fn reference<'a>(&mut self, reference: view::Reference<'a>,
        target: Visit<record::Context<'a>>, _: record::Context<'a>,
        out: &mut dyn Write) -> io::Result<()> {
        if reference.name() == "payload" {
            self.emit(target, out)
        } else {
            writeln!(out, "reference {}", reference.name())
        }
    }
}
let mut source = SchemaSet::new();
source.add::<Packet>();
let schema = AnalyzedSchema::analyze(source, &Bindings::new())?;
let mut text = Vec::new();
Text.emit_all(record::entries(&schema).filter(|v| v.name() == Some("Packet")), &mut text)?;
assert_eq!(text, b"payload.value\n");
# Ok::<(), Box<dyn std::error::Error>>(())
```

An output `entry` is a generator-selected starting point, not necessarily an
unreferenced graph root. The default entry collection includes named declarations
in dependency order and explicitly selected anonymous definitions.
`prepare_entries` accepts a selected subset. Canonical analysis/traversal still
exposes every definition, including anonymous ones.

Expansion changes the subtree being visited, not its output entry. Context keeps
`entry_id/name`, current `definition_id/name/origin`, and the occurrence ID
separate. Repeated expansions preserve distinct use-site ancestry; they never
call `entry` again. This permits mixed named and expanded uses without backend
scope stacks. Default reference handlers expand anonymous declarations; a target
can override that choice, or expand a named declaration through the same callback.

Register-map expansion uses analysis-prepared argument substitution and local
geometry. It does not unroll banks or compute absolute addresses. Formal parameter
names, actual bindings and the free parameter scope of expressions remain available
separately. A C-specific analysis pass may still calculate absolute record offsets;
the common graph does not impose that target policy.

The C record backend expands references into occurrence-specific accessors. Veryl,
SV and UVM retain named declarations and expand the values needed at each use site.
Physical storage projections remain distinct from source type references.

## Export without a storage policy

`generate` takes a caller-owned `std::io::Write`. It preflights the dependency
closure and checks all target entry names before emitting any bytes, then concatenates
root output in dependency order. Rendering failures can leave partial bytes.
Buffering, flushing and file publication are ordinary caller-owned I/O operations.
`ExportError` distinguishes analysis and backend failures and retains their sources.

For separate destinations, `prepare` returns bound `PreparedEntry` values with
source `name()`, stable `id()` and `emit()`. The generator selects the filename,
media type and writer; backend aliases name language symbols, not output files.
No output trait or artifact metadata is required.

Backends may override `value::Backend::check_entry` to reject invalid target names
or claim names in `EntrySymbols`. This default-noop hook runs before writing.
Generators combining record and register backends share one `EntrySymbols` and
prepare both groups before emitting either. `PrepareEntries` is also an ordinary
analysis pass; target preflight does not schedule or own output storage.

Generation runs once over the prepared entries. A renderer may buffer local syntax
sections, such as UVM member initializers, while visiting a declaration; this does
not require separate generation passes. Expressions are render leaves evaluated or
formatted by the shared semantic fold; the backend itself can implement
`ExpressionSyntax` without a separate syntax wrapper.

```rust
use std::io::{self, Write};
use hw_model_schema::{
    RecordSpec,
    analysis::AnalyzedSchema,
    export::{generate, record, value},
    export::record::Context,
};
#[derive(Default)]
struct NameListing;
impl record::Backend for NameListing {
    fn entry(&mut self, ctx: Context<'_>, writer: &mut dyn Write) -> Result<(), Self::Error> {
        writeln!(writer, "{}", ctx.entry_name())
    }
}
impl value::Backend for NameListing {
    type Error = io::Error;
    type Context<'a> = Context<'a>;
    type Domain = record::Domain;
}
let schema = AnalyzedSchema::opaque("Empty", RecordSpec::new(0, 1, &[]))?;
let mut output = Vec::new();
generate(&schema, NameListing, &mut output)?;
assert_eq!(output, b"Empty\n");
# Ok::<(), Box<dyn std::error::Error>>(())
```

Pass a `File`, `BufWriter` or `Vec<u8>` directly. Call `flush()` when required and
handle its I/O error in the application. For atomic publication, render into a
caller-owned temporary destination before publishing it. Source entry names are not
filesystem paths; target symbols and output paths remain separate decisions.

`prepare_entries` accepts explicitly selected bound root visits, allowing independent
domain backends to share one analyzed graph. Select each shared definition once
and check the combined target namespace before emitting. Do not deduplicate by
rendered bytes: distinct definitions with the same target name are a naming error.

## Optional `SystemVerilog` and UVM backends

These backends are available starting with 0.3. They require no simulator, UVM
library, application contract or runtime dependency
in Rust. Compilation of the generated SV/UVM remains an integration responsibility.

| Feature | Public backend | Output |
| --- | --- | --- |
| `export-sv` | `export::backends::system_verilog::SvRecordBackend` | Byte-image types, field accessors and enum/bit metadata; caller owns the package |
| `export-sv` | `export::backends::system_verilog::SvRegisterBackend` | Register/map layout packages and 64-bit unsigned parameterized layout functions |
| `export-uvm-regs` | `export::backends::uvm::UvmRegisterBackend` | Register and map classes; caller owns the UVM package/imports and runtime wiring |

All features are default-off. Each backend uses the same `prepare`, `prepare_entries`,
`generate` and `io::Write` interfaces as C/Veryl. `new()` selects source-derived names;
`with_name(NodeId, name)` overrides an entry name consistently, including UVM references.
Root names are preflighted. Nested generated symbols are checked before declarations;
a render failure can leave partial bytes, so use caller-owned buffering when atomic
file publication is required. A record-backend instance owns one package namespace;
use a new backend for another package. Retrying an entry clears only that entry's
previous symbol claims.

SV records represent encoded bytes (`byte n` occupies `[8*n +: 8]`), not a packed
struct mirroring Rust's native layout. Scalar accessors honor field endianness.
Named child records and unions have raw byte-envelope accessors; selection of an
untagged union is still a protocol decision. Logical case metadata is case-qualified.
Zero-sized images/accessors and images exceeding the signed 32-bit packed-index
range are explicitly rejected. Record sizes/offsets are emitted as 64-bit constants;
there is no silently truncated 32-bit size interface.

SV register packages contain metadata only, with no bus logic, storage or side
effects. They consume the same completed layout formulas, structural path names
and expression fold as Veryl. Fully bound inputs retain constant layouts; symbolic
inputs retain parameter functions. Permission-only views retain holes, original
indices and effective masks. Calls to generated layout functions must satisfy the
source layout constraints.

UVM target class names reserve the `uvm_` prefix and `type_id` for framework macros;
source names can be mapped to legal aliases. Framework types/constants are qualified
with `uvm_pkg::` and class-member references use `this.` to prevent name shadowing.
Class references also cannot share names with generated members or `build()`
arguments (such as `bus_bytes` or `p_count`). These conflicts are reported while
rendering; use `with_name` to select an unambiguous class alias. Repeated references
to the same class are supported.

UVM supports little-endian source registers/maps and uniform access within each
field. Partial writable fields, big-endian registers and authoritative permission-only
views are rejected. Value definitions are expanded at their register use sites;
they do not generate separate RAL classes. Constructors use `longint unsigned` for
schema parameters, and dynamic bank counts are checked before allocation. Shared
analysis permits binding standalone map entries, but rejects binding a definition
that is still referenced elsewhere; the backend reuses those rules.

Defaults are volatile fields with `UVM_NO_CHECK`; `PostReset` has no known hard
reset. `with_volatile(bool)` and `with_mirror_comparison(bool)` select target policies.
Enabling comparison does not create a predictor. The SV caller still configures the
base, calls `build(parameters..., bus_bytes)`, locks the model and attaches its adapter,
sequencer and prediction mechanism. Register write side effects are not inferred.

The annotated examples show package ownership and explicit flushing:

```sh
cargo run -p hw-model-schema --features export-sv --example sv_packages
cargo run -p hw-model-schema --features export-uvm-regs --example uvm_model
```

## Optional C11 fragments

The built-in C renderer is additive and default-off. Enable it only when the consumer
needs generic C11 record or register-map fragments:

```toml
[dependencies]
hw-model-schema = { version = "0.3.0", features = ["export-c-header"] }
```

With that feature enabled, the backend lives at
`export::backends::c_header`; optional backends are not nested outside `export`.
It streams deterministic C fragments through a writer and leaves include guards,
file layout, and integration policy to the caller.

Register symbols follow the complete structural path, including bank instance
indices. Each component uses C identifier escaping; an unrelated sibling or a
permission projection does not change the name of a surviving register. There is
no global short-name allocation or declaration-order numbering. To leave space
for the root prefix and property suffix, encoded path stems longer than 32 ASCII
bytes use their first 15 bytes, `_`, and a 16-digit uppercase FNV-1a64 digest of the
entire encoded stem. Final symbol checking rejects collisions, including collisions
within C's 63 significant identifier bytes. Explicit root-prefix overrides retain
their spelling and may therefore be rejected if they cause such a collision.
Final macro and scalar accessor function declarations use the same collision scope.

```rust
# use hw_model_schema::{
#     Decode, Encode, Endian, FieldSpec, SchemaCodec, RecordSpec, ScalarKind,
#     SchemaCodecError, SchemaMemberIdentity, SchemaLocation, read_scalar, write_scalar,
# };
#[cfg(feature = "export-c-header")]
fn main() {
    use hw_model_schema::{
        ast::{DefinitionId, SchemaSet},
        analysis::{AnalyzedSchema, Bindings, Pipeline},
        export::backends::c_header::{CRecordAnalysisPass, CRecordBackend},
        record_schema,
    };

    record_schema! {
        record Header {
            alignment: 4,
            endian: Little,
            fields: { value: u32, }
        }
    }

    let mut output = Vec::new();
    let mut selected = SchemaSet::new();
    selected.add::<Header>();
    let graph = selected.resolve().expect("example references must resolve");
    let schema = AnalyzedSchema::from_graph(&graph, &Bindings::new()).expect("example layout must resolve");
    let root = schema.definition(DefinitionId::of::<Header>()).expect("selected root");
    let prepared = Pipeline::new((&schema, ())).run(CRecordAnalysisPass).expect("C analysis must succeed");
    assert!(prepared.generate(
        |data| CRecordBackend::new(data).with_name(root.id.clone(), "demo header"),
        &mut output,
    ).is_ok());
    assert!(output.starts_with(b"#define C_DEMOQX20HEADER_SIZE"));
}

#[cfg(not(feature = "export-c-header"))]
fn main() {}
```

No Markdown, JSON, or PDF exporter is implemented. This crate does not provide `no_std`,
a callable C API, native-layout ABI casts, PCIe/MSI-X behavior, SR-IOV, FLR, or
hardware-specific effects.

## Constructor-bound register banks

Map placements use brackets for repetition: `pub channels: Channel[4]` or
`pub channels: Channel[channel_count] { offset: 16 }`.
Brackets preserve indexed identity even for `[1]`; the only placement option is
`offset`. Counts are integer literals or declared `usize` parameters. Stride is
always `align_up(child.extent(), child.alignment())`; declare reserved padding in
the child block's extent. Neither the DSL nor `RegisterBank::new(child, base, count)`
accepts a stride override.

Declare parameters with `pub map Device(channel_count: usize) { ... }`.
`Device::new(channel_count)` returns a checked, immutable `DeviceLayout`, containing
geometry rather than aggregate hardware values. Its `extent()` and typed placement
handles use the constructor-bound count. A child can receive parameters recursively:
`pub groups: Group(lanes)[groups]`. Parameterized child placements always produce an
instance layout, including literal arguments such as `Group(3)[1]`.

Each handle exposes `base()`, `count()`, `stride()`, checked `offset(index)`,
`locate(address)`, and `route(address, |index, child_offset| ...)`. Route closures
borrow caller-owned hardware and use the existing `RegisterAccessError` and
`register_dispatch!` protocol. A block reserves its complete address envelope,
including internal holes. Sibling placements cannot overlap a child or bank envelope;
group registers sharing one repeated slot inside a single child block. `locate` and
`route` select a child aperture so its own validation handles reserved holes.
`locate_instance` selects a configured
stride slot, including its padding, before the caller checks permissions and aperture
bounds; `finish_access` reports the terminal hole or
outside-window error after sibling dispatch. `rebased(parent_base)` translates a
bank into a parent address space without allocating hardware or metadata.

Static prefixes retain inferred `MEMBER_OFFSET` and `MEMBER_STRIDE` constants.
Fixed maps retain their `Copy` values, const extent, views and `RegisterWindow` API.
Explicit `resolve()` collects owned bank templates, counts, strides, documentation
and leaf ancestry. Access projection retains bank geometry when members are hidden.
C exports preserve flattened leaf symbols and include bank geometry plus parent
bank/instance links for nested banks.

Low-level `RepeatedRegisterBank` metadata retains descriptive strides. Both
`RegisterMapSpec::validate()` and `resolve()` reject overlap across complete bank
envelopes, including a scalar or another bank placed in an internal hole.

## Union composition

### Record-backed union cases

An inline `tagged_union` requires a `tag: self...` discriminator. The old inline
`union` spelling is rejected with a migration hint; replace that field keyword with
`tagged_union`. This syntax change does not alter generated Rust names or wire layout.

In addition to equal-width inline cases, a record union can reuse complete schemas:
```rust
# use hw_model_schema::{record_schema, SchemaCodecError};
# fn main() -> Result<(), SchemaCodecError> {
record_schema! { pub record Small { endian: Little, fields: { value: u16 } } }
record_schema! { pub record Large { endian: Little, fields: { first: u64, second: u64 } } }
record_schema! {
    pub record Packet {
        endian: Little,
        fields: {
            tag: enum(u8) { variants: { Small = 0, Large = 1 } },
            payload: tagged_union { tag: self.tag, cases: { Small(Small), Large(Large) } },
        },
    }
}

// Given: differently sized records selected by the union value.
let small = Packet::new(
    PacketTag::Large,
    PacketPayloadValues::Small(Small { value: 0x1234 }),
);
let large = Packet::new(
    PacketTag::Small,
    PacketPayloadValues::Large(Large { first: 7, second: 42 }),
);
// When: both variants are encoded.
let small_bytes = small.to_bytes()?;
let large_bytes = large.to_bytes()?;
// Then: the union determines each tag, and both records round trip.
assert_eq!(small_bytes.first(), Some(&0));
assert_eq!(large_bytes.first(), Some(&1));
assert_eq!(Packet::from_bytes(&small_bytes)?, small);
assert_eq!(Packet::from_bytes(&large_bytes)?, large);
# Ok(())
# }
```
All branches in that union use record syntax. Size and alignment are the maximum
of the selected record definitions, rounded for alignment. Encoding derives the
tag from the value; decoding rejects nonzero storage beyond the selected record.
Nested codec errors retain their rebased coordinates. The parent specification
marks an opaque union region; each branch retains its own record specification.
The C exporter emits nested-record OFFSET/SIZE constants, so separately exported
branch accessors can operate on that region without handwritten layout offsets.
With multiple inline unions in one record, raw word accessors and metadata are
prefixed by the union field name; a single inline union retains word0/word1 names.

### Packed enum union tags

A union can select an enum member of an inline `bits(storage)` field or a reusable
`bits(Name)` field with `tag: self.flags.kind`. The member must be an enum; an
ordinary integer or boolean bitfield cannot serve as a discriminator. Cases must
cover exactly the enum variants. Inline declarations are checked by the macro;
referenced enum types are checked by the generated exhaustive Rust matches.

```rust
# use hw_model_schema::{bits_schema, record_schema, SchemaCodecError};
# fn main() -> Result<(), SchemaCodecError> {
bits_schema! {
    pub bits Header(u16) {
        ready: 0..=0,
        kind: 4..=5 => enum { variants: { Small = 1, Large = 2 } },
    }
}
record_schema! {
    pub record Packet {
        endian: Little,
        fields: {
            header: bits(Header),
            payload: tagged_union { tag: self.header.kind,
                cases: { Small { value: u32 }, Large { first: u32, second: u32 } },
            },
        },
    }
}
let packet = Packet::new(
    HeaderValues { ready: true, kind: HeaderKind::Small },
    PacketPayloadValues::Large(PacketPayloadLargeValues { first: 7, second: 42 }),
);
let bytes = packet.to_bytes()?;
assert_eq!(packet.header.kind, HeaderKind::Large);
assert!(packet.header.ready);
assert_eq!(Packet::from_bytes(&bytes)?, packet);
# Ok(())
# }
```

Owned constructors and encoders derive the discriminator from the payload while
preserving other semantic fields in the same word. Separate unions can use
different enum members of that word. Existing checks for unknown enum values,
reserved bits, inactive union storage and sibling-field overflow still apply.
The containing record supplies the word's byte order; bit ranges remain LSB0.

Tag lookup remains local: `self.kind`, `self.header.kind` for a nested record enum,
or `self.flags.kind` for a bits member. It does not traverse to a parent record or
scatter a child record's fields. The C exporter retains its unshifted enum constants
and raw-word load/store interface; C callers pack the control word according to
the declared bit positions and select consistent payload bytes.

### Untagged complete-record unions

`union_schema!` overlays independently defined complete records at byte zero:

Its `union` declaration is untagged and cannot contain a `tag` clause. The caller
selects the case explicitly; use an inline `tagged_union` in a record when the wire
format carries a discriminator.

```rust
use hw_model_schema::{record_schema, union_schema};
record_schema! { pub record Small { endian: Big, fields: { value: u16 } } }
record_schema! { pub record Large { endian: Little, fields: { value: u64 } } }
union_schema! { pub union Packet { cases: { Small(Small), Large(Large) } } }
let value = Packet::Small(Small::new(0x1234));
let mut raw = PacketRaw::default();
value.encode_variant(raw.as_mut())?;
assert_eq!(Packet::decode_variant(raw.as_ref(), PacketCase::Small)?, value);
# Ok::<(), hw_model_schema::SchemaCodecError>(())
```

The explicit decoder takes `PacketCase`; the macro never infers or reads a selector.
`RECORD_SIZE` is the largest case extent rounded to the largest case `RECORD_ALIGNMENT`.
`ZERO` selects the first record's semantic zero. `PacketRaw` owns unvalidated bytes
and provides `new`, `as_bytes`, `into_bytes`, `Default`, `AsRef` and `AsMut`.
`PacketView` and `PacketViewMut` check extent at construction and expose
`variant(case)`; the mutable view also exposes atomic `set_variant(&value)`.
Decoding checks the selected record, its direct alignment gaps and trailing
padding, and the union's inactive tail. Nested records keep their own padding
policy; ordinary record decoding remains permissive about alignment padding.
Encoding uses temporary fixed-size storage, zeros inactive bytes, and commits
only after the selected record encodes successfully.

By default the union has no `Decode`, `Encode`, `SchemaCodec`, `to_bytes`, or
`from_bytes` and needs no application codec hooks. `Packet::SPEC` describes only
opaque storage extent and alignment. Export each case's ordinary `SPEC` alongside
it when consumers need field accessors; no selector metadata is generated.

An optional `codec: external` clause generates mechanical adapters for an
application-provided codec:

```rust
use hw_model_schema::{Decode, Encode, SchemaCodec, SchemaCodecError, record_schema, union_schema};
record_schema! { pub record Small { endian: Big, fields: { value: u16 } } }
record_schema! { pub record Large { endian: Little, fields: { value: u64 } } }
union_schema! {
    pub union Packet {
        cases: { Small(Small), Large(Large) },
        codec: external,
    }
}
impl SchemaCodec for Packet {
    fn decode(bytes: &[u8]) -> Result<Self, SchemaCodecError> {
        // This application always interprets incoming storage as Small.
        Self::decode_variant(bytes, PacketCase::Small)
    }
    fn encode(bytes: &mut [u8], value: &Self) -> Result<(), SchemaCodecError> {
        value.encode_variant(bytes)
    }
}
let value = Packet::Small(Small::new(0x1234));
assert_eq!(value.encode()?.decode()?, value);
assert_eq!(PacketView::new(&value.to_bytes()?)?.values()?, value);
# Ok::<(), SchemaCodecError>(())
```

The opt-in adds value `Encode`, raw `Decode`, fallible conversions in both
directions, value `from_bytes`, `encode_into` and `to_bytes`, immutable-view
`Decode`, both views' `values()`, and mutable-view `set_values(&value)`.
The union always implements `SchemaLayout` with `Value = Self`. The application
implements only `decode` and `encode` in `SchemaCodec`; all
generated codec paths call that trait's `decode` and `encode`. Missing trait
implementations or required methods fail compilation. Implementations can live
in another module; the views and adapters are generated at the union declaration.
Keep `decode`/`encode` independent of the generated convenience methods to
avoid recursive calls.

The schema adds no selector requirement, inference, protocol validation, or
callback trait. Application trait implementations own case selection, validation, errors, and
write atomicity; adapters preserve their behavior. View construction checks only
extent and clips the borrow to the union size. `variant(case)` and
`set_variant(&value)` remain explicit structural operations even with the opt-in,
so they do not apply application codec policy. The example's fixed-case decoder
needs no selector at all. Inline `tagged_union` behavior is unchanged.


`SchemaLayout` owns the associated value and view types, geometry, metadata, zero
value, structural padding validation and checked view constructors. Generated
records and untagged unions implement it, including unions without a codec.
`SchemaCodec: SchemaLayout` adds only `decode` and `encode`. Record fields and both
record-backed union forms compose through that shared contract.
A case `Case(Codec)` stores `<Codec as SchemaLayout>::Value`; a codec can be a
handwritten struct, enum, or marker with a different value type. Implementors
implement both traits, with no required inherent constants or methods. Generated
records implement both traits automatically.
A raw untagged union must implement `SchemaCodec` before it can be nested;
`codec: external` only adds convenience adapters around that implementation.
The opt-in conveniences require `Value = Self`; generic composition also supports
manual marker codecs with a different value type without the opt-in.
Case-selection policy remains application-owned.
Tagged fields obtain their discriminator from their parent record as before.

`SchemaLayout::SPEC` defaults to opaque extent/alignment metadata and can be
overridden for structural export. Generated records preserve their rich metadata.
Composers do not interpret child metadata to guess padding: the selected codec
receives its exact extent, then the enclosing union checks only its inactive tail.
`SchemaLayout::validate_padding` defaults to success; generated records override it to check
their direct gaps when selected as complete untagged cases. Ordinary record
and tagged-case decoding retain their existing gap tolerance. Nested opaque
codecs validate their own representation through `decode`, including nonzero
payloads. Parent encoders use temporary storage so even a child error after
writing cannot partially modify the parent's destination.
